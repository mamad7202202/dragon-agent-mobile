The memory system

Dragon offers two swappable memory engines. Both are on-device, work offline, and are always available to the model during every turn.

🧠

Hybrid (classic)

Semantic facts scored per-turn with lexical cosine similarity × importance × a two-week recency decay, plus MEMORY.md rules and resumable sessions. Rich, fuzzy, battle-tested.

🗺️

Outline (infographic)

Memory as hierarchical sections of one-line bullets — profile, preferences, projects, people, goals, facts. Injected as a compact outline so the model spends a few hundred tokens, not thousands.

Choosing an engine

Settings → Memory → Memory engine. Switching is instant and non-destructive: both stores live side by side on disk (facts.json and graph_memory.json), so you can flip back and forth. MEMORY.md rules and sessions are shared by both engines.

How Outline mode works

The model maintains the outline itself through tools, and the whole structure is re-injected every turn:

[MEMORY OUTLINE]
profile: Name is Mamad; Lives in Tehran; Works on AI agents;
preferences: Answers in Persian; Prefers dark UI;
projects: Dragon Agent — Rust desktop agent; Mobile port in Flutter;
people: Sister called Sara;
goals: Ship Play Store release this year;
  • memory_write(section, bullets) — upserts one-liners (≤140 chars). Identical or near-identical bullets are refreshed, never duplicated.
  • memory_delete(id | section) — removes stale entries (gated behind user approval).
  • memory_read() — dumps the full outline for auditing.

Why it's token-efficient without being lossy

  • Every bullet is self-contained — no dangling context across entries.
  • Sections are ranked against your message when the outline grows, so truncation (if any) drops the least relevant sections first, never mid-thought.
  • Dedupe + 160-char cap keep the outline dense instead of sprawling.
  • Anything too rich for a bullet still belongs in MEMORY.md rules or the session transcript — outline mode doesn't replace those.

How Hybrid mode works

score = tf_cosine(query, fact)
      × (0.55 + 0.45 × importance)
      × (0.7  + 0.3  × recency)      recency = 1 / (1 + age_days / 14)

Top-k facts (k = 6) are injected each turn. The agent saves new facts via save_memory when it notices something durable. Old turns fold into an LLM summary once history passes the compaction threshold.

Procedural memory — MEMORY.md

Standing rules that are always loaded, in both modes. Edit under Memories → Rules, or let the agent append via the remember_rule tool (approval-gated). Example:

- Always answer in Persian
- My timezone is +3:30
- Never suggest cloud services I didn't ask about

Episodic memory — sessions

Every conversation is a resumable transcript on device. Browse and reopen them from Settings → Sessions; compaction keeps long ones inside the context window by folding old turns into summaries.
