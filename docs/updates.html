docs / updating

Updates that stack

The app updates itself from GitHub releases. You never uninstall to upgrade, and your keys, memories and sessions survive every update.

flowWhat happens

  1. When your device comes online — and once at launch — the app checks the rolling latest release.
  2. A newer version gets a banner over the chat. You can also check manually in Settings → Check for updates.
  3. Tapping it downloads the APK with a live progress bar, then opens the system installer.
  4. The new version installs over the old one. Done.

trustWhy installs stack cleanly

Android only allows an in-place upgrade when the signature and package id match and the version number increases. Dragon signs every release with the same committed keystore, keeps one applicationId, and bumps the build number each release — so each build is a normal upgrade of the last.

One-time exception: builds before v1.1.0 were signed with a per-build debug key. Uninstall that old build once, install v1.1.0 or newer, and every update after that stacks forever.

semverVersion scheme

  • X.Y.Z — semantic version, defined in pubspec.yaml.
  • +N — the Android build number; increases every release so the installer always accepts the newer package.
  • Every push to main is tagged vX.Y.Z, published as a formal release and as the rolling latest.

iosOn iOS

Apple doesn't allow in-app self-installation. The banner opens the releases page instead — re-sideload with Sideloadly or AltStore as usual.
