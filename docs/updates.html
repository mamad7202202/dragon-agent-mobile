Updating

The app updates itself — no Play Store, no reinstalls.

How it works

  1. Whenever your device comes online (and once at launch) the app checks the rolling latest release on GitHub.
  2. If a newer X.Y.Z exists, a banner slides in over the chat. Manual checks also live in Settings → Check for updates.
  3. Tap به‌روزرسانی / Update → the APK downloads with a live progress bar → tap Install.
  4. The system installer opens; the new version installs on top of the current one. Your keys, memories, outline, rules and sessions all survive.

Why updates stack cleanly

Every release is signed with the same committed keystore and ships the same applicationId with a monotonically increasing version code — Android treats each build as a normal in-place upgrade.

One-time note: if you installed a very early build (v1.0.x) signed before the stable key existed, uninstall it once and install v1.1.0+ fresh. Every build after that updates over the previous forever.

Versioning scheme

  • X.Y.Z — semantic version, source of truth in pubspec.yaml.
  • +N — Android build number, bumped every release so the installer always accepts the newer package.
  • Every push to main is tagged vX.Y.Z and published both as a formal release and as the rolling latest.

iOS

Apple doesn't allow in-app self-installation of IPAs, so on iOS the update banner opens the releases page — re-sideload with Sideloadly/AltStore as usual.
